# Beancount 自动导入工具文档

## 预研日期：2026-09-26

## 结论摘要

建议建设一款本地优先、以人工审核为最终控制点的 Beancount 导入工具。它的价值不在于重写每一种账单解析器，而在于把多来源账单解析、跨来源归一化、语义分类、Beancount 校验与可重复导出组织成一个安全闭环。

当前研究方向见 [多来源归一化与 LLM 语义分类](research-direction.md)。流水线是：分源提取、归一化为 `AccountingEvent`、用确定性规则判断收支或转账类型、由 LLM 在已有账户中选择费用或收入账户，最后交给 Fava Import 审核。0.1 预研中的来源隔离和专用文件写入仍然有效；“规则优先于模型”的分类顺序不再指导实现。

推荐的研发路径：

1. 保持现有 CSV 垂直切片：Beangulp importer → Fava Import 页面 → Beancount 输出与校验。
2. 用 Beangulp importer 作为 Beancount 接入契约，继续复用 Fava 的提取预览、编辑和写入界面。
3. 自研范围集中在来源记录、跨来源关联、`AccountingEvent` 和事件类型；匹配只建立关联，不销毁来源记录。
4. 语义分类使用受限 LLM。账户必须来自账本已打开账户；失败时进入 suspense，由 Fava 人工修改。
5. 用真实支付宝和银行样本评估匹配与分类接受率后，再扩展更多来源适配器。

## 需要在立项时确认

- 首批真实账单样本：支付宝、微信、至少一种银行借记卡和一种信用卡。解析器选择必须以样本回归测试为准。
- GUI 是第一版必须项还是第二阶段项。预研建议先证明导入与审核闭环，再投资完整 GUI。
- LLM endpoint、模型和 suspense 账户名；分类器默认关闭，配置后才调用。

## 预研范围与限制

本文档描述当前原型的公开设计和使用边界。候选项目调研、许可证核对和个人学习笔记保留在本地，不作为公开项目的稳定 API 或承诺。
