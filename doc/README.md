# Beancount 自动导入工具文档

## 预研日期：2026-09-26

## 结论摘要

建议建设一款本地优先、以人工审核为最终控制点的 Beancount 导入工具。它的价值不在于重写每一种账单解析器，而在于把账单解析、账户映射、跨来源去重、分类建议、人工修正、Beancount 校验与可重复导出组织成一个安全闭环。

开源项目已经分别解决了很多底层问题，但没有一个已核实项目同时满足：支付宝/微信/国内银行覆盖、从人工修改生成个人规则、跨平台对账、可定制输出和易用的审核 GUI。建议不要在没有真实账单验证前把产品绑定到单一项目。

推荐的研发路径：

1. 先以旧 CSV 映射逻辑做首个垂直切片：Beangulp importer → Fava Import 页面 → Beancount 输出与校验。
2. 用 Beangulp importer/hook 作为 Beancount 接入契约，优先复用 Fava 已有的上传、提取预览、编辑和写入界面；先验证目标账本的写入路由。
3. 自研范围集中在来源数据/会计事件模型、跨来源关联与信息合并、事件解析，以及规则优先的分类建议；匹配只建立关联，不销毁或压平来源记录。
4. 用 Python 和 Beancount 3 生态逐步接入支付宝、微信和银行 importer；确认许可证与真实账单兼容性后才锁定依赖。
5. 人工确认后可生成规则草稿，用户回放并确认后才启用。Fava 内建 UI 不足时再开发专用审核界面。`smart_importer` 可作本地 ML provider；LLM 是可选建议器且默认不联网。

## 需要在立项时确认

- 首批真实账单样本：支付宝、微信、至少一种银行借记卡和一种信用卡。解析器选择必须以样本回归测试为准。
- GUI 是第一版必须项还是第二阶段项。预研建议先证明导入与审核闭环，再投资完整 GUI。
- 本地 LLM 的运行方式、可接受硬件和模型授权；MVP 不依赖 LLM。

## 预研范围与限制

本文档描述当前原型的公开设计和使用边界。候选项目调研、许可证核对和个人学习笔记保留在本地，不作为公开项目的稳定 API 或承诺。
